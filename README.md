# 实时语音识别系统

**把通话双方的话分角色实时转成文字。** 客服的声音走左栏，客户的声音走右栏，各出一条独立的文稿，通话结束自动存成 WAV + TXT + JSON。

基于 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) + SenseVoice，**全程在本机离线运行** —— 音频不出本机，不需要联网，不依赖任何云端 API。

## 特性

- **双声道分角色转写**：用两块声卡把客服和客户物理隔开，比算法分离说话人可靠得多
- **两遍识别**：单块结果先上屏保证实时感，静音处再整句重识别回填标点
- **完全离线**：模型本地推理，录音和文字都不出本机
- **自动归档**：每通电话存 `WAV`（录音）+ `TXT`（纯文稿）+ `JSON`（带时间戳的分段结果）

## 工作原理

音频按 **3 秒**切块，每块走两条路径：

```
麦克风/虚拟声卡 → 16kHz PCM → WebSocket → 3s 分块 → 降噪 → VAD
                                                          │
                        ┌─────────────────────────────────┴──────────────────┐
                        │                                                    │
                  第一遍：单块识别                                     第二遍：整句重识别
                  （去掉标点，立刻上屏）                          （VAD 检测到连续静音即切句，
                        │                                          拼回完整句子重新识别，带标点）
                        │                                                    │
                        └────────────→ 前端按区间覆盖组装 ←──────────────────┘
```

第一遍响应快但断句碎、没标点；第二遍准但有延迟。前端用第二遍的结果**覆盖**同一时间区间的第一遍结果，兼顾实时感和文稿质量。

## 环境要求

- **Windows**（依赖 WASAPI 音频设备和 VB-CABLE 虚拟声卡）
- **Python 3.8+**
- 约 **300 MB** 磁盘空间（模型占 229 MB，首次启动自动下载）

## 快速开始

### 1. 装依赖

```bash
pip install -r requirements-sherpa.txt
```

> `webrtcvad` 必须装上。缺了它程序**不会报错**，但语音边界检测会失效，第二遍标点修正退化成"每 30 秒硬切一次"。

### 2. 启动

```bash
python main_sherpa.py
```

首次运行会自动下载语音模型（约 229 MB）到 `models/`，**有进度条，要等几分钟**。下载完浏览器打开 <http://127.0.0.1:8001> 即可。

想要独立的桌面窗口而不是浏览器标签页：

```bash
python launcher.py
```

### 3. 配好两路声音

这是唯一需要动手配置的地方：

| 面板 | 声音来源 | 怎么接 |
|---|---|---|
| **客服** | 你的麦克风 | 默认设备即可 |
| **客户** | 通话对端的声音 | **需要一块虚拟声卡** |

客户声道要拿到"对方从扬声器里传出来的声音"，得靠虚拟声卡把系统播放的声音回灌成一路输入设备：

1. 安装 [VB-CABLE](https://vb-audio.com/Cable/)（免费）
2. 在通话软件里把**扬声器输出**设为 `CABLE Input`
3. 在页面底部的「客户源」下拉框里选 `CABLE Output`

程序会自动检测虚拟声卡并帮你选上。如果两个声道选到了**同一个设备**，页面底部会提示"两栏内容会重复" —— 这时转写出来的两边是一模一样的。

> 页面底部还会显示「音量过大」提醒，在客户音量持续偏大时弹出，用于及时注意沟通状态。

## 配置

改 `.env.sherpa`（不是 `.env`），改完重启生效：

```ini
SHERPA_NUM_THREADS=4       # 推理线程数，核多可调大
SHERPA_USE_INT8=true       # int8 量化版，快；false 用 fp32，准
MODELS_DIR=./models        # 模型目录，相对路径按程序所在目录解析
CHUNK_SECONDS=3.0          # 音频分块时长
ENABLE_NOISE=false         # 降噪，默认关闭
VAD_AGGRESSIVENESS=2       # VAD 灵敏度 0-3，越大越容易判为静音
#SAVE_DIR=./results        # 结果保存目录，不设则见下
```

**关于 `SAVE_DIR`**：不设置时默认存在程序目录下的 `results/`；如果那里写不进去（例如装到了 `Program Files` 而当前不是管理员），会**自动改存到** `文档\SherpaASR\results`。页面底部可以随时改路径，改完会校验目录能否创建和写入。

> ⚠️ **采样率必须是 16000 Hz。** 程序启动录音前会硬校验，不是 16k 就拒绝开始并给出提示 —— 因为按错误采样率解码会得到语速失真的乱码，而且不会有任何报错。如果被拦下，去「系统声音设置 → 录制设备 → 属性 → 高级」把设备采样率改成 16000 Hz。

## 输出文件

每通录音存成一个以开始时间命名的目录：

```
results/2026-09-09T02-36-37-733Z/
├── agent.wav      # 客服声道原始录音（16kHz 单声道）
├── agent.txt      # 客服文稿（按句子分段）
├── agent.json     # 带时间戳的分段结果
├── client.wav     # 客户声道
├── client.txt
└── client.json
```

`json` 里的 `segments` 记录每段文字对应的起止时间，方便做通话复盘：

```json
{
  "start": 0.0,
  "end": 12.0,
  "text": "你好，我想咨询一下这个业务。",
  "source": "merge"
}
```

> **注意**：两个声道的 `start`/`end` 是**各自相对各自连接的开始时间**，不是同一时钟。目前两条轨道之间无法直接对齐。

## 项目结构

```
main_sherpa.py     FastAPI 服务 + 两条 WebSocket 管线
asr_sherpa.py      sherpa-onnx 封装、模型下载、输出清洗
vad.py             基于 webrtcvad 的语音活动检测
denoise.py         降噪（分块处理，默认关闭）
config_sherpa.py   配置加载
launcher.py        桌面窗口启动器
index.html         前端（单文件，无构建步骤）
installer.nsi      NSIS 安装包脚本
```

## 打包

- `sherpa-asr.spec` —— PyInstaller 配置
- `installer.nsi` —— NSIS 安装包脚本

> **目前 spec 不能直接用**：它的入口写的是 `win7/launcher.py`，依赖 `win7/` 和 `hooks/` 两个目录，这三个都没包含在本仓库里（那是给 Win7 兼容构建用的分支）。要打包需要先把入口改回 `launcher.py`，并去掉这几处引用。另外第 34-35 行的 OpenSSL DLL 路径是打包者的本机路径，也需要按自己的环境改。

## 已知限制

- **超长句会被硬切**：连续说话超过 30 秒（10 个块）会被强制切断，可能在句中截断
- **英文/日文词间空格会丢**：输出清洗会移除所有空白字符，`hello world` 会变成 `helloworld`。中文不受影响
- **降噪是分块的**：逐 3 秒独立降噪，块边界有拼接伪影；如果开启降噪后整句结果反而变差，是这里的原因
- **交换声道不改变落盘文件名**：界面上交换「客服/客户」标签后，文件仍按连接时的声道名保存，事后对不上角色
- **结果目录不会自动备份**：`results/` 已被 `.gitignore` 排除，不会被 Git 备份
